# Portfolio Case Study — AI Business Analyst Workbench

## Overview
A prototype that supports the early stages of business and systems analysis for a fictional procurement process.

## My role
Business Analyst / Solution Designer (portfolio simulation).

## Problem
Purchase requests are submitted through inconsistent channels, approvals are distributed across email, and requesters have limited status visibility.

## Approach
1. Defined the business problem and stakeholder groups.
2. Drafted a project charter and discovery questions.
3. Created functional and non-functional requirement catalogues.
4. Modeled As-Is and To-Be process flows.
5. Designed a conceptual solution and identified integration questions.
6. Built a small workbench to generate draft requirements, BRD sections, process observations, and UAT scenarios.
7. Added a sample n8n intake workflow with validation and human-review status.

## Deliverables
- Business problem statement and project charter
- Stakeholder analysis
- BRD and requirement catalogues
- Process models and solution architecture
- UAT plan
- Streamlit prototype
- AI prompt templates and evaluation rubric
- n8n workflow skeleton

## Limitations
This is a fictional case study. The application uses transparent keyword rules when no AI API is configured. It is not connected to a production ERP and does not execute purchase approvals.

## What I learned
The project demonstrates how structured requirements, process modeling, AI-assisted drafting, and human review can work together. In a real project, the next step would be stakeholder validation and baseline measurement before implementation.
