# Stakeholder Analysis

| Stakeholder | Interest / concern | Information to obtain | Engagement |
|---|---|---|---|
| Requester | Easy request submission and status visibility | Required fields, pain points, accessibility | Interview and prototype review |
| Procurement Officer | Complete requests and manageable workload | Validation rules, categories, exception handling | Workshop and process walkthrough |
| Department Manager | Correct approval authority | Approval matrix, delegation, escalation | Approval-rule validation |
| Finance | Budget and cost-center correctness | Budget checks, accounting fields | Requirements review |
| IT / Application Support | Security, supportability, integration | Identity, logging, interfaces, recovery | Technical review |
| Internal Audit | Traceability and evidence | Audit fields, retention, access | Control review |

**Note:** Stakeholder roles are proposed for the fictional case and must be confirmed in a real project.
